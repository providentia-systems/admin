# Household metadata and product display — API 2.2.0

Admin mirrors the exact backend-owned API 2.2.0 artifact, JSON SHA-256 `ef5714a6298326d6fb449b966117e8b61c74de67d1bfc274ad8ec431aecd802d`. Its generated facade remains the existing 92-operation operator allowlist; no household tenant mutation endpoints are added. Bindings are regenerated by the existing generator, never hand-edited.

## Readable household product columns

Homes → selected home → Products displays the effective Product, Brand, Pack and Category before the raw identity and override fields. Backend #25 resolves private names and packs first, then linked catalog values. Its existing operator-record envelope now includes read-only name, brand, pack_text, category_name, category_scope and catalog_reference columns. This correction does not require a contract change or an additional migration.

A catalog-linked product can legitimately have no private_name or original_pack_text override. Those columns are explicitly labelled Private name override and Private pack override, and show No private override when unset. They are not populated with copied catalog values. Real missing references show Unresolved product or an explicit missing/mismatched catalog-reference status, with the original IDs retained for diagnosis. Names remain visible for private products, uncounted products, family-only links and archived catalog identities. Home-bound category resolution, stable 100-row paging and operator authorization/auditing remain unchanged.

## Household editing and quantity entry

Backend #25 and household Client #21 add household-only name/pack overrides, explicit stock-unit labels, and selection of a published global or local category. The household Client exposes these controls in spaced scrollable forms. Private product changes retain identity, quantities, revision safeguards and synchronization history; shared catalog values are not rewritten. Global category selection does not publish a private product. Stock units are labels (units, g, kg, ml, l), not automatic balance/history conversions.

The Client quantity dialog now contains only the observed quantity, Cancel and Save. It has no reason dropdown, reason text field or Other explanation. The existing audited adjustment command automatically supplies Stock count correction. Routine manual counts remain reason-free. This removes household reason input without removing stock history or changing Admin's privileged audit-reason requirements.

The product-table correction is not a replacement operator editor. Existing Admin catalog CRUD/search, audit reasons and household private-product/category management remain intact. Backend operator stock responses expose effective household metadata; the broader operator customization editor remains a separate scope. The existing Admin update omits new global/unit fields and therefore preserves those selections unless explicitly changed through a supported command.
